# Code of Conduct Conversations in Open Source Software Projects on Github

**Authors:** Renee Li, Pavitthra Pandurangan, Hana Frluckaj, Laura Dabbish
**Published:** 2021, Proceedings of the ACM on Human-Computer Interaction, Vol. 5, CSCW1, Article 19, pp. 1-31
**DOI:** 10.1145/3449093
**Link:** https://dl.acm.org/doi/10.1145/3449093

## Abstract

The rapid growth of open source software necessitates a deeper understanding of moderation and governance methods currently used within these projects. The code of conduct, a set of rules articulating standard behavior and responsibilities for participation within a community, is becoming an increasingly common policy document in open source software projects for setting project norms of behavior and discouraging negative or harassing comments and conversation. This study describes the conversations around adopting and crafting a code of conduct as well as those utilizing code of conduct for community governance. We conduct a qualitative analysis of a random sample of GitHub issues that involve the code of conduct. We find that codes of conduct are used both proactively and reactively to govern community behavior in project issues. Oftentimes, the initial addition of a code of conduct does not involve much community participation and input. However, a controversial moderation act is capable of inciting mass community feedback and backlash. Project maintainers balance the tension between disciplining potentially offensive forms of speech and encouraging broad and inclusive participation. These results have implications for the design of inclusive and effective governance practices for open source software communities.

## AI Summary

This CSCW study moves beyond the question of whether CoCs exist in OSS projects to examine how communities actually discuss, adopt, and invoke codes of conduct in practice. The research uses qualitative methods to analyze real conversations happening in GitHub issues that reference or involve a project's code of conduct.

The methodology involved identifying GitHub issues that mention or are related to codes of conduct, then conducting a systematic qualitative analysis (content analysis following established coding methodologies) on a random sample of over 400 such issues. The researchers developed a coding scheme to categorize the types of conversations occurring around CoCs, identifying distinct patterns in how communities engage with these governance documents.

The study identifies two primary modes of CoC usage: proactive and reactive. In the proactive mode, project maintainers or community members invoke the CoC to set expectations before conflicts arise — for example, reminding contributors of behavioral expectations in heated discussions, or using the CoC as a reference point when onboarding new contributors. In the reactive mode, the CoC is invoked after a violation occurs, used to justify moderation actions such as comment removal, warnings, or bans.

A critical finding is the "participation paradox" in CoC adoption: the initial proposal to add a CoC to a project typically involves minimal community discussion or input. Most CoC proposals receive few comments or reactions, and the document is often merged without significant deliberation. However, when a controversial moderation decision is made using the CoC as justification, this can trigger enormous community backlash. This asymmetry — quiet adoption followed by contested enforcement — creates governance problems because the community never collectively agreed on the norms being enforced.

The study also documents the tension maintainers face between two competing values: maintaining a welcoming, inclusive environment (which requires moderating offensive speech) and fostering broad participation (which requires tolerating diverse viewpoints). Some maintainers resolve this tension by treating the CoC as a floor (minimum acceptable behavior) rather than a prescription, while others use it more actively to shape community culture.

The implications for governance design are significant: the researchers recommend that projects engage their communities more deeply in CoC creation and deliberation, rather than simply adopting a template. They also suggest that transparent moderation practices — where the reasoning behind enforcement decisions is visible — can reduce backlash and build legitimacy.
